| 2026-09-29 | **Major discovery during Part 0.4 B2 setup:** confirmed B2 connectivity (bucket `satilliate-images`, endpoint `https://s3.us-east-005.backblazeb2.com`, read scope verified) and found the bucket already contains a `vizag-geoai/` prefix with **existing processed outputs**, not just raw data: `data/boundaries/gvmc_boundary.geojson` (+ buffered version) and `data/processed/sentinel2/2018/masked/...` per-scene reflectance/SCL/QA products for tiles T44QPE/T44QQE/T44QQF. This means prior work on this project produced real outputs that survived in B2 even though the local codebase was deleted — exactly the scenario the storage-tier design is meant to protect against. **Implication:** Phase 1 (boundary) and Phase 3 (preprocessing) may be partially or fully done already; do not blindly rebuild without first running Phase 2 Part 2.1's inventory to catalog what exists, verify its provenance/trustworthiness, and decide reuse vs redo. Also contradicts Assumption A4 — the sampled keys aren't raw `.SAFE`/`.zip`, so the raw archive's actual location/prefix in this bucket is still unknown. See `open_questions.md` for full A1–A5 status. |
| 2026-09-29 | Resolved a lengthy B2 credential debugging saga (Part 0.4): the `.env` vars are named `Backbaze-keyID`/`Backbaze-applicationKey`/`BUCKET-ID` (not the plan's placeholder names). Root cause of repeated `InvalidAccessKeyId: Malformed Access Key Id` errors: the user was repeatedly regenerating the **Master Application Key's secret**, whose `keyID` always equals the 12-character Account ID — which B2's S3-compatible gateway rejects even though it's valid for B2's native API (confirmed via a direct `b2_authorize_account` call, which succeeded throughout). Fix: created a genuine non-master Application Key (25-char `keyID`, 31-char secret) scoped to the bucket. Also fixed: `BUCKET-ID` env var holds B2's internal bucket ID (hex), not the S3 API's required bucket *name* (`satilliate-images`, obtained from the console). No secret values were ever printed to logs/tracking/committed files during this process — only lengths/prefixes/suffixes were used for diagnosis. |

Flagged a plan gap: `plan.md`'s Phase 0 test list doesn't name any test for `validation.py` even though it's an explicit Part 0.3 deliverable used by every later phase — wrote 18 tests for it anyway (additive, not a deviation).
