| 2026-09-29 | Resolved a lengthy B2 credential debugging saga (Part 0.4): the `.env` vars are named `Backbaze-keyID`/`Backbaze-applicationKey`/`BUCKET-ID` (not the plan's placeholder names). Root cause of repeated `InvalidAccessKeyId: Malformed Access Key Id` errors: the user was repeatedly regenerating the **Master Application Key's secret**, whose `keyID` always equals the 12-character Account ID — which B2's S3-compatible gateway rejects even though it's valid for B2's native API (confirmed via a direct `b2_authorize_account` call, which succeeded throughout). Fix: created a genuine non-master Application Key (25-char `keyID`, 31-char secret) scoped to the bucket. Also fixed: `BUCKET-ID` env var holds B2's internal bucket ID (hex), not the S3 API's required bucket *name* (`satilliate-images`, obtained from the console). No secret values were ever printed to logs/tracking/committed files during this process — only lengths/prefixes/suffixes were used for diagnosis. |
